# Mimir v7 — Restricted Direct P2WSH Script

Status: pre-mainnet preview  
Template: `mimir-direct-p2wsh-v1`

This specification describes only the implemented v7 page and compiler.

## 1. Policy language

The user registers one to five public keys and authors one to five alternative
clauses. Any one satisfied clause can spend.

```text
POLICY = OR(CLAUSE 1, ..., CLAUSE N)
CLAUSE = OPTIONAL_ABSOLUTE_CLTV AND SIGNATURE_THRESHOLD
```

Each clause contains:

- one to five distinct registered keys;
- an integer threshold `K`, where `1 <= K <= N`; and
- either no lock or one whole-day Unix timestamp at `00:00:00 UTC`.

No other Boolean nesting, hashlock, relative lock, custom opcode, or arbitrary
Script input is accepted. Labels are descriptive only.

## 2. Literal Script construction

One clause compiles directly to its clause body. Multiple clauses compile in
authored order as a right-nested conditional:

```text
OP_IF
    CLAUSE 1
OP_ELSE
    OP_IF
        CLAUSE 2
    OP_ELSE
        CLAUSE N
    OP_ENDIF
OP_ENDIF
```

A clause body is exactly:

```text
# optional
<timestamp> OP_CHECKLOCKTIMEVERIFY OP_DROP

# one selected key
<public_key> OP_CHECKSIG

# or two to five selected keys
K <public_key_1> ... <public_key_N> N OP_CHECKMULTISIG
```

Selected public keys are ordered lexicographically inside a threshold. No
clause is normalized, factored, merged, reordered, or removed. Repeated public
keys remain explicit across branches.

## 3. Branch witnesses

For `N` clauses, selectors are documented bottom-to-top in the manifest:

| Clause | Selector items, bottom-to-top |
|---|---|
| first | `1` |
| second | `1 0` |
| third | `1 0 0` |
| last | only `0`, repeated once for each preceding branch |

The one-clause case needs no selector. Selector items must be minimally encoded
as the empty vector for false or `0x01` for true.

`OP_CHECKMULTISIG` witnesses require a leading empty dummy item. Signatures
must be ordered to match the selected public keys' Script order. The manifest
records the key order, dummy requirement, selectors, clause ASM, and clause hex.

## 4. Inputs

| Item | Rule |
|---|---|
| Registered keys | 1–5 |
| Clauses | 1–5 |
| Keys per clause | 1–5 distinct registered keys |
| Threshold | integer `K`, `1 <= K <= N` |
| Label | non-empty, unique ignoring case, at most 80 characters |
| Public key | valid 33-byte compressed secp256k1 point |
| Lock type | absolute timestamp only |
| Date granularity | `00:00:00 UTC` whole day |
| Timestamp range | `500000000..4294944000` |
| Latest UI date | `2106-02-07` |
| Networks | Mainnet, Testnet, Signet, Regtest |

The compiler accepts historical locks for reproducibility. The page requires a
future date for new clauses and blocks address copying/export if an open
session crosses a saved lock date.

## 5. Request

```json
{
  "format": "mimir-direct-script-policy-request",
  "version": 7,
  "network": "regtest",
  "template_id": "mimir-direct-p2wsh-v1",
  "keys": [
    {
      "id": "owner",
      "label": "Owner",
      "public_key": "0279be667ef9dcbbac55a06295ce870b07029bfcdb2dce28d959f2815b16f81798"
    }
  ],
  "clauses": [
    {
      "key_ids": ["owner"],
      "threshold": 1,
      "unlock_unix": null
    }
  ]
}
```

Keys are canonically ordered by public key and assigned stable `key-NN` IDs.
Keys inside each clause use that order. Clause order remains authored order
because it maps directly to the visible branch structure and witness selector.

## 6. Output

Successful compilation returns:

- normalized request and canonical manifest;
- exact flat Bitcoin Script ASM;
- exact witness-script bytes and hex;
- opcode and signature-operation counts;
- P2WSH witness program and scriptPubKey hex;
- network-specific P2WSH address;
- one manifest entry per clause, including its exact body ASM/hex and witness
  construction metadata;
- SHA-256 of the exact canonical manifest bytes.

Address prefixes are `bc1q` for Mainnet, `tb1q` for Testnet and Signet, and
`bcrt1q` for Regtest. Network changes the address encoding, not the witness
script.

## 7. Safety boundary

The compiler directly constructs typed instructions and serializes them to
bytes; it does not parse generated ASM back into Script. It enforces the
3,600-byte standardness bound and 201-op bound. The test suite independently
parses generated bytes and compares their symbolic result with every authored
signer subset at each lock boundary.

CLTV requires the spending transaction's `nLockTime` to meet the clause
timestamp and this input's `nSequence` to be non-final. Timestamp locks use
median time past. `CHECKMULTISIG` requires the empty dummy witness item.

This direct Script is not a general spending descriptor. A generic descriptor
wallet is not sufficient recovery metadata. The policy JSON, exact witness
script, branch selectors, signature ordering, and a rehearsed recovery tool
must be retained. Bitcoin Core transaction construction, signing, OP_RETURN
metadata, funding, broadcast, and monitoring are outside v7.
